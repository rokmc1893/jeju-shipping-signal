## 검증 범위

- 가격이 있는 행만 날짜순으로 정렬했다. 마지막 가격, 최근 7개·30개 행의 산술평균, 그 직전 7개 행과의 변화율을 계산했다. 전년 비교는 조회 기준일의 전년도 같은 날짜 ±3일에 포함된 거래 가격의 평균과 비교한다. 자료가 7일을 넘겼을 때는 기준일의 전년 비교와 현재 판단을 보류한다.
- 서버와 독립된 CSV 계산, HTTP 응답의 실제 거래일·품종·통계·조건별 판단과 점수, 앱에서 각 버튼을 눌러 표시한 거래일·가격·두 평균·전년 비교 또는 보류 사유·신호·조건 수를 대조했다. 가중치와 외부 모델은 사용하지 않았다. 표의 가격은 전국 도매 관측값이다.
- 날짜별 수집 기록은 각 품종 74회, 5품종 합계 370회다. 기상 수집은 0회다. 수집 요청 성공 여부와 최신 자료 존재 여부는 따로 점검했다. 달력에 행이 없는 날짜의 사유는 미확인이다.
- 품목 없는 질문 되묻기, 당근 전년 비교 질문, 전년 자료 없는 과거 기준일의 가격 유지, 기상 자료 없음, 물량 환산 가정 표기를 HTTP로 확인했다. 고정된 테스트 자료로 미래 행 제외와 전년 비교창의 양 끝, 7일·8일 경계를 재검증했다.
- 검증 중 발견한 상자 가격·거래일 오표시를 수정했다. 원/kg을 강조하고 환산은 가정임을 표시한다. 화면에 남아 있던 ‘오늘’ 표현을 고치고, 오래된 거래의 판정을 보류한다. 물량 API의 기존 응답 키는 호환성을 위해 유지했다.
- 맥 pytest 100개와 프론트 빌드를 통과했다. code-reviewer가 수정본을 재검토했다. GitHub에서 프론트 빌드 이후 npm audit가 기존 picomatch 4.0.7 경고로 실패했다. 패치 버전이 발표되지 않아 병합은 보류한다. [보안 공지](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)

## 가격·단위와 경고 해석

제공처는 제주데이터허브, 원천은 aT도매유통정보시스템이다. 상세 페이지의 출력 항목에서 평균 도매가격은 원/kg, 거래량은 톤, 거래금액은 백만원으로 확인했다. 페이지의 수집기간 표기는 2025-10-31에 끝나지만, 이번 API 수신분에는 2026-11-17 자료까지 있다. 조회 결과의 최신일은 실제 캐시로 판별한다. 포장당 kg이나 산지는 이 데이터셋의 출력 항목에 없다. [공식 데이터 설명](https://www.jejudatahub.net/data/view/data/1361)

- 단위를 맞춰 계산한 가격×거래량과 제공 거래금액의 절대 상대오차 중앙값은 8.92%다. 평균가격의 집계 방식은 확인하지 못했다. 표기된 단위를 유지하고 평균가격은 원천 필드를 사용한다. 거래금액에서 가격을 역산하거나 상자 무게를 확정하는 근거로 쓰지 않는다.
- 기상 CSV 부재 경고는 거래 통계만 수집한 결과다. 기상 비교는 검증 대상에서 제외했다.

## 재현

저장소 루트에서 아래 첫 명령은 API를 호출한다. 기존 캐시를 다시 검사할 때는 두 번째 명령만 실행한다.

```sh
DATA_DIR=data/cache .venv/bin/python scripts/collect.py --no-weather --item carrot --default-only
.venv/bin/python scripts/validate_cache.py --data-dir data/cache --asof 2026-11-18 --item carrot --default-only --json
```

해당 시점의 로컬 보고서는 `outputs/validation/carrot-20261118.json`이다. 보고서·CSV·수집 상태 파일 모두 Git 제외를 확인했다. 다음 검사는 고정 기준일의 도매가격·7/30거래일 평균·전년 비교를 독립 계산해 당근 API와 화면의 표시값과 대조하는 것이다.
