## 이번에 고친 결함

- LLM을 켜면 버튼 조회에서도 설명 호출이 일어났다. 자유 질문에서만 설명을 생성하도록 제한했다.
- 단위 검증 상태를 반대로 넘겨 미확인 환산 각주가 빠졌다. 상자·망 무게를 미확인으로 두고 기준을 표시했다.
- 기상 수집 중 리스트를 재할당해도 실행 중 반복자가 바뀌지 않았다. 관측소별 연속 빈 응답을 세고 중단할 관측소를 따로 관리한다.
- 원클릭 실행에서 프론트 빌드가 빠졌다. 최초 빌드를 수행하고 설치·빌드 실패 시 종료한다.
- Python 3.10에서 사용할 수 없는 f-string 문법을 고쳤다.
- 임의 품목·잘못된 품종·음수 물량·미지원 의도 입력이 서버 오류를 만들 수 있었다. HTTP 입력을 검증한다.
- 합성 무 품종명이 실제 설정과 달랐다. `월동무`로 맞췄다.
- 합성 캐시 생성기가 실데이터를 덮어쓸 수 있었다. 실데이터가 있는 폴더에서는 거부하고 합성 자료는 화면·각주에 표시한다.
- 기상 자료 부족 안내가 화면에서 사라졌다. 자료 부족 이유를 패널로 표시한다.
- 모바일 품목 타일의 최소 너비로 화면이 밀렸다. 좁은 화면의 열 수와 입력창 배치를 조정했다.
- 비활성화한 시장 비교를 자주 묻는 질문에서 추천하고 있었다. 해당 바로가기를 제거했다.

## 다음 기술 보완

기상 수집 예산은 실행당 제한이며, 하루 누적 사용량·실패 재시도는 합산하지 않는다. 실행 중단 후 빈 응답 날짜도 다시 호출한다. 호출 이력과 체크포인트를 저장하는 보완이 필요하다.

수집기의 일부 오류는 로그만 출력하고 정상 종료한다. 새 캐시가 전혀 없으면 실행 스크립트가 중단하지만 부분 수집 성공·실패를 명확히 구분하는 종료 코드와 품목별 상태가 필요하다. 품종 전체 수집이 끝나기 전 중단되면 해당 품종의 진행분을 잃을 수 있다.

날씨와 가격의 비교는 계절성·거래량·이벤트 중복을 통제하지 않았다. 인과관계나 가격 예측으로 설명해서는 안 된다. 실제 기상 갱신 지연도 재확인해야 한다.

LLM 설명은 프롬프트만으로 숫자·색·예측 표현을 제한한다. 기본값은 `none`이며 버튼은 호출하지 않지만, 모델을 사용하는 자유 질문 경로에는 응답 사후 검증이 필요하다. 모델의 센터 GPU 적재 가능성도 실제 측정 전이다.

차트는 올해·작년 거래일 순서로 정렬해 날짜가 정확히 일치하지 않을 수 있다. 달력 기준 정렬 또는 명확한 축 설명이 필요하다. 연속 요청의 응답 순서, 키오스크 초기화 중 요청, 장시간 실행도 추가 확인 대상이다.

현재 CSS·폰트와 음성 기능을 포함한 완전한 오프라인·인쇄 검증은 하지 않았다. 프론트 번들 크기 경고와 Starlette TestClient의 httpx 사용 중단 예고가 남아 있다. Python 의존성은 범위 지정으로 설치되어 완전한 버전 고정도 남아 있다.
