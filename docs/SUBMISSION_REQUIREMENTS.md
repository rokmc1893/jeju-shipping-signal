# 출하 신호등 제출본 요구사항 · 2026-11-18

센터 PC를 처음 쓰는 도민이 **당근을 한 번 누른 뒤, 어느 날의 전국 도매가격인지, 작년과 비교할 수 있는지, 왜 그 신호가 나왔는지** 읽을 수 있어야 한다. 사용자에게는 출하를 판단할 참고 자료를 제공한다. 이 문서에서 확정한 것은 동작 기준이며 아래 합격 검사는 후속 단계에서 실행한다.

## 제출 범위

| 우선순위 | 결정 |
| --- | --- |
| 필수 | 센터 PC에서 실행하는 화면, 당근(일반) 실제 거래 조회, 가격·거래일·출처·원/kg 표시, 추세·전년 비교 또는 계산 불가 사유, 신호 설명, 품목을 되묻는 경로를 제공한다. 버튼 조회는 외부 LLM 호출 없이 동작한다. |
| 조건부 | 월동무·양배추(일반)·깐마늘·조생양파는 당근과 같은 검사를 통과한 품종부터 공개한다. 기상은 관측소·기간·표본이 확인된 경우에만 보조 정보로 표시한다. 개발 중에는 갤럭시 에뮬레이터로도 같은 결과를 확인한다. |
| 후속 | 공개 서버 운영, 스토어 출시, 네이티브 음성 입력, 시장별 추천은 이번 제출의 완료 조건에서 제외한다. |

## 사용자 흐름과 합격 검사

**첫 화면 → 품목 선택 → 거래일·가격 읽기 → ‘왜 이 색?’ 확인 → 다른 품목 선택**이 기본 경로다. 질문에 품목이 빠졌으면 선택지를 거쳐 같은 결과 화면으로 돌아간다. 아래 문구는 의도와 표시 위치를 설명하는 예시다.

| 번호 | 입력 또는 화면 상태 | 사용자가 확인할 동작과 통과 기준 | 검증 결과를 남길 단계 |
| --- | --- | --- | --- |
| R01 | 첫 실행, 검증된 품목과 자료 없는 품목이 함께 있음 | 조회 가능한 품목을 선택할 수 있다. 준비 중인 품목에는 이유를 표시한다. 합성 캐시에서는 첫 화면과 결과에 시연용임을 알린다. | 화면 검증 |
| R02 | 당근(일반) 선택 | 실제 품종·마지막 거래일·원/kg·전국 도매 기준을 표시한다. 원자료를 독립 계산한 가격이 API와 화면에서 표시 단위까지 일치한다. | 당근 데이터·통합 검증 |
| R03 | ‘왜 이 색?’과 전년 비교 열기 | 30거래일 평균 대비 가격, 7거래일 추세, 전년 동기 조건을 각각 수치 또는 판단 불가 사유로 설명한다. 화면의 색·한글 신호명이 계산 규칙과 일치한다. | 통합 검증 |
| R04 | 기준일에 행이 없고 이전 거래는 있음 | 기준일과 실제 거래일을 구분한다. 마지막 자료가 1~7일 전이면 ‘마지막 거래일 기준’으로 안내한다. 8일 이상이면 가격 옆에 마지막 날짜와 경과 일수를 표시한다. 누락 사유가 확인되지 않으면 휴장으로 단정하지 않는다. | 1·7·8일 경계값 화면 검증 |
| R05 | 품종 자료 없음, 전년 자료 없음, 수집 일부 실패 | 전체 자료가 없으면 가격·신호를 생성하지 않는다. 전년 자료만 없으면 확인 가능한 현재 가격과 ‘전년 비교 자료 부족’을 함께 표시한다. 미완료 구간은 고지하고, 해당 구간에 의존하는 수치나 판단은 보류한다. | 데이터·화면 검증 |
| R06 | 질문 ‘작년보다 비싸요?’에 품목이 없음 | 품목을 되묻고 선택 후 해당 품목을 조회한다. 품목이 명시된 질문에서는 선택한 도구와 결과의 연결을 실행 기록에서 확인할 수 있다. | Agent 통합 검증 |
| R07 | 당근 조회 중 무 선택, 또는 서버 연결 실패 후 재시도 | 대기 중인 품목을 식별할 수 있고 이전 가격을 새 품목 가격처럼 표시하지 않는다. 연결 실패는 자료 없음과 다른 안내를 보여준다. 연결 복구 후 다시 조회할 수 있다. | 화면 검증 |
| R08 | 상자·망의 kg 근거 미확인 | 기본 가격은 원/kg으로 읽을 수 있다. 품목 버튼부터 결과·물량 계산까지 미확인 중량으로 확정 금액을 안내하지 않는다. 규격 근거를 확보하면 검증된 단위로 환산한다. | 단위·화면 검증 |
| R09 | 새 PC에서 매뉴얼만 보고 실행 | 사용자는 키 설정·최초 수집·앱 실행·당근 조회를 재현할 수 있다. 비개발자가 가격·거래일·신호 이유를 찾는지 확인한다. 센터 직접 실행과 대체 환경 결과를 구분한다. | 설치·사용성 검증 |

현재 코드에는 자료 없는 품목의 비활성화, 조회 중 표시, 오래된 자료 경고, 신호 설명이 있다. 후속 검증에서 우선 확인할 차이는 세 가지다. 품목 버튼은 단위 검증 여부와 관계없이 상자·망 중량을 표시한다. 새 요청을 시작해도 이전 결과가 화면에 남을 수 있다. 품목에 행이 있다는 사실만으로는 수집이 끝났는지 알 수 없다. 근거는 [품목 화면](../frontend/src/App.tsx), [판단 엔진](../backend/app/judge.py), [품목 API](../backend/app/main.py), [품목 설정](../config/items.yaml)이다.

## 공식 제출 요건과 확인 방법

마감은 **2026년 11월 20일 오전 10시**다. 갤러리에서 기획서와 최종 ZIP을 제출한다. 아래 체크박스는 제출 전 실물 점검용이다. [DAKER 대회 안내](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)

- [ ] 센터 또는 허브 자료를 1종 이상 실제 사용한다. 첫 대상은 허브의 ‘농산물 품종별 일일 거래 통계’(1361)다. 데이터 활용 명세에서 출처·사용 필드·전처리·이용조건을 확인한다.
- [ ] 15쪽 이내 기획서에서 문제와 사용자, 서비스, Agent 역할·도구·자율 판단, 데이터 활용, 센터 탑재·의존성을 확인한다.
- [ ] ZIP에는 실행 소스·프롬프트·도구, 설치·사용 매뉴얼, 데이터 활용 명세, 결과 설명자료 네 항목이 들어 있다. 압축을 풀고 설명서대로 실행한 기록을 남긴다.
- [ ] 실제 사용한 AI 모델·도구의 역할과 외부 서비스·데이터·코드·라이브러리를 밝힌다. 데이터 키 발급·설정 방법을 제공하고 비밀키·개인정보·개발 사진은 제외한다.
- [ ] 제출 계정에서 첨부 파일과 제출 완료 상태를 확인한다.

| 미확인 사항 | 확인할 시점과 처리 |
| --- | --- |
| 공개 허브 API 캐시 | 운영자가 심사용 ZIP 동봉을 허용했다. 공개 저장소에는 원자료를 넣지 않고 ZIP 안에 출처·기준일·가공 과정을 적는다. |
| 센터 환경 | 운영자 안내는 Windows 11 26H2이며 인터넷 설치가 가능하다. 서명 없는 확장 모듈의 허용 등록과 첫 실행은 별도 확인한다. |
| 포장 규격 | 원천은 원/kg이다. 품종별 포장 중량 근거를 확보하기 전에는 R08을 적용한다. |

상호평가에는 기획서만 공개된다. 필수 ZIP과 기획서 외의 데모 링크·GitHub·영상은 선택 항목이다. 세부 근거는 [공식 질의응답 재검토](JUDGING_REVIEW.md)에 기록했다.
